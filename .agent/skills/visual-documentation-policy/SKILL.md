# Goal
システムの構造、データの流れ、状態の遷移などをユーザーが直感的に理解できるよう、テキストによる説明に加えてMermaid形式の図を積極的に活用する。

# Instructions

## 1. 適用範囲
このルールは、以下のドキュメントを生成・更新する際、またはチャットで仕様を解説する際に必ず適用されること。
- `.agent/tasks/task.md` （初期要件の整理）
- `.agent/tasks/qa.md` （仕様のすり合わせ、エッジケースの確認）
- `.agent/tasks/plan.md` （作業ステップ、タスクの依存関係）
- `README.md` （アーキテクチャ概要、システム仕様）

## 2. 図解の積極的な活用
テキストのみの平坦な説明を避け、以下の基準に従って適切なMermaid図を生成・挿入すること。

- **シーケンス図 (`sequenceDiagram`):**
  - ユーザーとシステム間のインタラクションを説明するとき。
  - 複数のコンポーネント、API、外部サービス間でデータがやり取りされる処理の流れを定義するとき。
- **状態遷移図 (`stateDiagram-v2`):**
  - システムの状態（例: 待機中 → 実行中 → エラー/完了）が変わるプロセスを説明するとき。
  - 条件分岐が複雑なロジックを整理するとき。
- **クラス図 (`classDiagram`):**
  - データモデル、データベースのスキーマ、主要なオブジェクトとその関係性（Pydanticモデルの構造など）を定義するとき。
- **フローチャート (`graph TD` / `graph LR`):**
  - `.agent/tasks/plan.md` における作業の依存関係や、全体的な処理のワークフローを概観するとき。

## 3. 記述ルール
- Mermaidコードは必ずMarkdownのコードブロック（````mermaid ... ````）で囲むこと。
- 複雑すぎる巨大な図は避け、コンポーネントや機能ごとに分割してシンプルで読みやすい図を心がけること。
- 図だけでなく、その図が何を表しているのか、重要なポイントはどこかをテキストでも簡潔に補足すること。
