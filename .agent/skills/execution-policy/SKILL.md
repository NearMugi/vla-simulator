# Goal
安全なバージョン管理、ステップバイステップの確実な進行、および適切なドキュメント・ライセンス管理を徹底しながら実装を進める。

# Instructions

## 1. Git操作の制限
- **許可される操作:** `git add` によるステージングまでは自律的に実行してよいこと。
- **制限される操作:** `git commit` および `git push` は、原則としてユーザーからの明示的な指示があるまで実行してはならないこと。
- **例外事項:** 他のリポジトリのコードを `git merge` （または `pull`）した直後に発生する自動マージコミットについては、この制限の例外とすること。

## 2. プランに基づくステップ実行
- 常に `.agent/tasks/plan.md` に記載されたステップ（タスク）単位で作業を進めること。
- 一度に複数のステップをまとめて実行しないこと。
- 一つのステップの作業が完了したら、必ずチャット上でユーザーに報告し、次のステップに進んでよいか（または修正が必要か）の確認を入れること。
- ユーザーからの「OK」「次へ」などの承認を得た後、次のステップの作業を開始すること。
- 完了したステップについては、`.agent/tasks/plan.md` の該当するチェックボックス（`[ ]`）を `[x]` に更新して保存すること。

## 3. ドキュメントとライセンスの徹底
- プロジェクトのルートディレクトリには、必ず `README.md` を作成（または更新）すること。
- `README.md` にはプロジェクトの概要、セットアップ方法、実行方法を記載すること。
- **著作権/ライセンス表記:** 実装においてサードパーティのOSSライブラリ（Pythonパッケージなど）を使用した場合は、必ずそれらのライセンス情報（MIT, Apache 2.0など）や著作権表記を `README.md` 内にセクションを設けて明記するか、別ファイル（例: `LICENSE` や `THIRDPARTY.md`）に記載した上で `README.md` からリンクして参照できるようにすること。
